# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repo identity

PyQt6 instrument-control suite for a confocal/quantum-optics setup driving NI-DAQmx hardware, Thorlabs piezo, PulseBlaster, AWGs, GPIB sources, lasers, spectrometers, and several auxiliary rigs (FLIM, OCT, UHV). This is the **`master`** branch — the kitchen-sink superset. Several focused branches strip it down (`Confocal-Only`, `AWG`, `PicoHarp`, `FLIM`, `2ch_confocal`, `Holonomic-Control`, …). Do not merge across branches without checking with the user — the branches are intentionally divergent rigs, not parallel development of the same code.

## Setup

```bash
# Install uv
curl -LsSf https://astral.sh/uv/install.sh | sh                  # macOS / Linux
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"       # Windows

uv sync                       # core deps
uv sync --extra windows       # add pythonnet (Thorlabs Kinesis piezo, Windows only)
```

Hardware drivers are **not** pip-installable. See `driver.md` for NI-DAQmx and Thorlabs Kinesis install per OS, expected `Dev1` device name, and the Thorlabs piezo serial number (`44533394`).

### Known pyproject gaps on master

- `mainexp_gui.py` imports `qdarkstyle` and `PyDAQmx` but `pyproject.toml` lists neither. `PyDAQmx` is **vendored** at `instruments/PyDAQmx/` (resolved via `sys.path` from `run.py`). `qdarkstyle` is missing entirely — add it (`uv add qdarkstyle`) before launching master, or guard the import.
- `pyproject.toml` on master is closer to the Confocal-Only dep list than to what `master` actually imports. Treat it as best-effort; expect missing deps to surface at first launch and add them.

## Running

```bash
uv run python run.py
```

`run.py` is a 4-line bootstrap that prepends both `ROOT` and `ROOT/gui` to `sys.path` and `runpy`-executes `gui/confocal_gui.py` as `__main__`. **Note:** on `master`, the real main GUI is `gui/mainexp_gui.py` (class `MainExp_GUI`, ~3100 lines). If `confocal_gui.py` is not present on this branch, point `run.py` at `gui/mainexp_gui.py` or run that file directly with the same `sys.path` setup. Other rigs have their own entry scripts in `gui/`:

| Entry | Purpose |
|---|---|
| `gui/mainexp_gui.py` | Main experiment GUI (confocal + sweep + APD + spectrometer + PicoHarp + SatCurve + batch + terminal) |
| `gui/flim_main.py` | FLIM analysis viewer (loads a `.mat` of TCSPC + intensity + tau) |
| `gui/OCT_gui.py` | OCT acquisition GUI |
| `gui/UHV_System_gui.py`, `gui/UHV_LakeShore_gui.py`, `gui/UHV_heat3_gui.py`, `gui/UHV_xr40b_gui.py` | UHV chamber controllers (LakeShore temp, heater, etc.) |
| `gui/MATBrowser.py`, `gui/ConfocalBrowser.py` | Offline `.mat` browsers (no hardware) |

`uv run python gui/<entry>.py` after ensuring `gui/` is on `sys.path` (or wrap with a `run.py`-style bootstrap).

## Architecture

### Qt Designer + pyuic6 convention

Every GUI module is a pair: `<name>.ui` (Qt Designer XML) → `<name>_gui.py` (or sometimes just `<name>.py`, e.g. `mainexp.py`) generated by `pyuic6`. The hand-written `*_gui.py` / `*_main.py` controller imports the generated file as `mainwindow` and multiply-inherits from `QMainWindow` + `Ui_MainWindow`. **Do not edit the generated file** — every regeneration overwrites changes. Pattern: edit the `.ui` in Designer, regenerate with `pyuic6 -o gui/<name>_gui.py gui/<name>.ui`, then wire signals in the controller.

The widget naming convention is load-bearing: `btn_*` / `chkbx_*` / `dbl_*` / `int_*` / `linein_*` / `tab_*` / `cbox_*`. `TaskHandler` and user scripts reach into the main window by name (e.g. `self.mainexp.dbl_confocal_x_start.setValue(...)`), so renaming a widget in Designer can silently break scripts.

### Thread architecture

All hardware control runs on QThread workers that inherit from `experiments.ExpThread.ExpThread`. The main window owns one instance of each (`self.thread_confocal`, `self.thread_sweep`, `self.thread_tracker`, `self.thread_liveapd`, `self.thread_seqapd`, `self.thread_spectrometer`, `self.thread_picoharp`, `self.thread_satcurve`, `self.thread_batch`, `self.thread_terminal`, …). Threads talk back to the GUI only via PyQt6 signals; scripted workflows synchronize via per-thread `QMutex` + `QWaitCondition` pairs (`self.wait_<exp>`) — the worker emits `signal_wait_for_mainexp` after queuing GUI work and waits on the condition so all earlier signals flush before continuing.

`ExpThread.save_data` and `ExpThread.run_script` are inherited by every worker. `run_script(filename)` execs a Python file from `~/Documents/exp_scripts/<filename>` with **every callable on `TaskHandler` bound as a global**, plus `self`, `mainexp`, and `pb`. That is the scripting surface: a user writes a script that just calls `confocal(...)`, `track()`, `setval(...)`, `setexp(...)`, etc., and it Just Works inside the running app.

### PulseMaster + `pb_functions/` hot-load

`instruments/PulseMaster.py` (`PulseMaster`, subclasses `PulseBlaster.PBESRPro`) is the pulse-sequence engine. The actual sequences live in `pb_functions/` as paired free functions:

```python
def pb_<name>_params(self): ...   # populates self.params
def pb_<name>(self):              # emits pb instructions via self.add_inst(...)
```

`pb_functions/import_pb_functions.py` scans `locals()` after the files are `exec`'d, finds every `pb_<name>` that has a matching `pb_<name>_params`, and attaches both as bound methods on the `PulseMaster` instance, registering `<name>` in `self.pulse_list`. Numbered families group experiments: `001-002` basics, `003-004` calibration (T1, multi-pulse), `100-102` dynamical decoupling / DEER, `200-202` quantum reporter / Dutt protocol, `300` charge-state readout, `400` trigger plumbing, `500-501` PLE / two-color. **Adding a new pulse sequence = drop a `pb_<name>` / `pb_<name>_params` pair into one of these files; do not modify `PulseMaster` to register it.**

### Configuration (not in-repo)

`mainexp_gui.py` reads runtime config from `~/Documents/exp_config/`:

| File | Purpose |
|---|---|
| `inst_params.yaml` | Instrument list — drives instantiation in `MainExp_GUI.__init__` (channel mapping, addresses, scaling) |
| `sweep_params/manual.yaml` | Default values for the "Manual" sweep params group |
| `variable_dict.csv` | Variable-name aliases used by the sweep / scripting layer |

There is **no `exp_config/` dir checked into master** — the GUI prints `inst_params.yaml not found!` and proceeds with empties until you provide one. Persisted GUI state (window geometry, last-used values) is pickled to `guisettings.config` via `file_utils.save_config` / `load_config`.

### Data I/O

`file_utils.save_data(filename, dict, graph=, fig=, sweep_params=)` writes:

- `~/Documents/data_mat/<filename>.mat` — scipy `savemat` of the experiment data
- `~/Documents/graphs_mat/<filename>.png` — optional, if `graph=` provided
- `~/Documents/figs_mat/<filename>.png` — optional, if `fig=` provided
- `~/Documents/data_mat/<filename>.yaml` — sweep parameters sidecar

`file_utils.getwavenum()` finds the next free `IMG_NNNN` number by scanning the data dir; `ExpThread.save_data` increments `self.mainexp.wavenum` after each save. The convention `<dataname>_<int>` is parsed by splitting on `_` and taking the last token — keep dataset names underscore-free except for the index suffix.

### Fitting / image processing (pure Python, no hardware)

- `fitters.py` — `scipy.optimize.curve_fit` wrapper-delegating framework. Adding a new fit = add the function, register it in the fitter, and it appears in the sweep tab's fit-type combo (`mainexp_gui.py` populates `cbox_fittype` from `thread_sweep.fitter.fit_functions`).
- `akl_image_processing.py` — stripe-pattern detection via coarse/fine angle search + variance optimization.
- `lifetime_functions/` — FLIM lifetime fitting helpers + a `LUT.csv`.

## Hardware support matrix

Full table is in `driver.md`. Short version:

| | Windows | Linux | macOS |
|---|:---:|:---:|:---:|
| Galvo XY scan + APD count (DAQmx) | yes | yes | no |
| Thorlabs piezo Z | yes | no | no |
| PulseBlaster (spinapi.dll/.so) | yes | yes (with kernel module) | no |
| GPIB instruments | yes | yes | n/a |
| Camera (`CAP_MSMF`) | yes | needs `CAP_V4L2` swap | needs `CAP_AVFOUNDATION` swap |
| Offline `.mat` browse / fit | yes | yes | yes |

On non-Windows, `gui/mainexp_gui.py` will fail at import time unless the Thorlabs/PulseBlaster/PyDAQmx-dependent imports are guarded — macOS is realistic only for offline data work via `MATBrowser.py` or `flim_main.py`.

## Branch hygiene

The remotes carry several long-lived branches that are each tailored to a physical rig: `master` (everything), `Confocal-Only`, `AWG`, `PicoHarp`, `FLIM`, `2ch_confocal`, `Holonomic-Control`, `motor`, `QDS`, `nidaqmx-dev`. Treat them as siblings, not as a development → trunk flow. Before porting a change, confirm with the user that the target branch wants it.
